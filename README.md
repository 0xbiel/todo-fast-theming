# Cerebras Board Studio

React/Vite board with local browser tasks. Live app: https://todo-fast-theming.vercel.app/ . `npm run dev`, `npm test`, `npm run build`. Node 24.x is declared for Vercel; local checks also ran on Node 20. No ONE or ModRetro source is involved.

## Board and presentation

Tasks have title, description, priority and status. Compact cards open a native dialog; Cancel/Escape discards drafts, Save/Ctrl+Enter commits. Custom menus support keyboard navigation. Drag cards/handles between statuses; handles also support left/right keyboard movement. Tasks stay in localStorage, never Supabase. Four rising bars and labels retain priority meaning; Urgent is red in Midnight and can change color in generated themes.

On visual-lab, AI changes presentation through validated RGB colors, font/density/layout enums, bounded declaration-only CSS, and decorative SVG rebuilt as trusted React elements. The legacy format still supports eight ellipse/rectangle/line decorations. The expressive format supports paint, local fonts, paths, gradients and patterns; arbitrary selectors, layout changes, scripts, events, foreignObject, external references and raw HTML injection are rejected. SVG has a 160-node, eight-depth, 400-segment/point and 16,000-character budget. Paint-server references cannot recurse, pattern spacing remains at least 16 after pattern transforms, and local IDs are isolated per rendered instance. Background artwork cannot capture pointers. Valid-schema model color choices get trusted contrast repair before strict validation; executable fields, unknown fields, geometry and complexity limits are never repaired. Task text surfaces remain opaque. The permanent bottom-center glass pill retains its trusted styling. Errors preserve the last good style; Undo restores the previous style.

Restyle never generates pretend results in production. Explicit mocks require both Vite DEV mode and VITE_ENABLE_MOCK=true. Unconfigured production reports setup required; Random is then a labeled local preset. Dictation is opt-in browser speech recognition, may use vendor servers, and is not supported everywhere.

## Cerebras limits and failure handling

Latest user-requested configuration: qwen-3.8-27b, reasoning_effort=none, reasoning_format=parsed, max_completion_tokens=32768. This is the current model maximum, not literal unlimited output. Reasoning and final output share this cap; reasoning is discarded. A strict JSON schema is sent; final content is validated on server and client. There are no automatic paid retries.

Transport receives at most 1 MiB, final JSON at most 256 KiB; renderer complexity is separately bounded. Provider deadline is 45 seconds, browser deadline 90 seconds, Vercel function maximum 90 seconds, and new accounting leases 120 seconds. Invalid/incomplete output fails closed without displaying reasoning or raw responses. Safe error codes distinguish auth, setup, approval, quota, rejected API key/model configuration, truncation, network failure and invalid output. Diagnostics contain only allowed finish reasons and numeric completion usage. Consumed usage is settled even when the design is rejected. Unknown dispatched usage retains the full reservation; only undispatched work may be cancelled/refunded. Exceeding usage bounds trips a durable budget breaker.

Official references: [public model catalog API](https://inference-docs.cerebras.ai/api-reference/models/public-models), [current Qwen metadata](https://api.cerebras.ai/public/v1/models/qwen-3.8-27b), [reasoning](https://inference-docs.cerebras.ai/capabilities/reasoning), [structured output](https://inference-docs.cerebras.ai/capabilities/structured-outputs), [Vercel durations](https://vercel.com/docs/functions/configuring-functions/duration). Catalog checked 2026-10-02: 65,536 context, 32,768 maximum completion, input $0.99/M and output $1.49/M. Reserve 4,096 input plus 32,768 output: ceil to **52,880 micro-USD ($0.052880)** per shared request. Twenty maximum-size requests reserve **$1.0576**, below the approved $5 aggregate UTC-day budget. Reviewed rates must be updated if prices change; outside account usage and taxes are not controlled by this ledger.

## Accounts and key custody

Supabase endpoint: https://sezokkremtxvznshoauv.supabase.co . SDK uses PKCE with explicit once-per-page code exchange, persisted-session reconciliation and auth-event synchronization. Callback failures are visible. Only an application JSON 401 with code auth may refresh once across consecutive failed requests; a manual retry that still fails reports an account-configuration problem instead of looping. Hosting-platform/non-JSON 401 responses never refresh app auth. Style POSTs include existing same-origin hosting-access cookies but still require verified bearer authentication, never follow redirects, and never retry automatically. The server verifies each token using auth.getUser and requires confirmed email; it never trusts browser claims. Connected appears only after a valid provider result and clears on a failed style request or identity/key change. Signed-in users are not told to sign in again merely because no AI request has succeeded yet.

Owner-approved shared access uses the private policy email allowlist. Unapproved users require their own key plus verified sign-in. Owner Cerebras keys stay exclusively in server secret configuration. BYOK is saved only in the user's browser; backend handling is transient and never logged/persisted. It never enters Supabase, snapshots, task data or source. Browser storage is accessible to same-origin scripts. A saved BYOK key takes precedence over shared access: users wanting owner-approved mode must remove their saved personal key themselves. The app never silently clears it or falls back to spending an owner key after a BYOK failure.

Default-SMTP email restrictions and OAuth provider setup need operational verification. OAuth UI availability is explicit: VITE_ENABLE_GOOGLE_AUTH=true or VITE_ENABLE_GITHUB_AUTH=true only after that provider is configured. Passwordless mode is VITE_PASSWORDLESS_MODE=link or code. Provider callback: https://sezokkremtxvznshoauv.supabase.co/auth/v1/callback . Production Site URL/allowed redirect: https://todo-fast-theming.vercel.app/ . Local auth redirect, if approved: http://127.0.0.1:5173/ . No wildcard redirects are needed.

## Local real BYOK

Run `npm run dev` and `npm run start:byok`; ignored .env.local needs VITE_ENABLE_LOCAL_BYOK=true. Open http://127.0.0.1:5173/, Account → Your own API key → Save locally → Restyle. This loopback-only path uses a process-local capability and exact host/origin checks, not a Supabase identity or shared-key grant. Durable SQLite accounting limits the whole local API to three requests per UTC day and concurrency one. Startup makes no provider call. Keys/prompts never enter the SQLite ledger. Python 3 and a local durable volume are required; SQLite is not used in Vercel functions.

`npm run start:api` is the optional authenticated local composition using ignored .env.local and the same-origin Vite proxy. Keep data outside served paths; the ledger supports processes sharing one local durable SQLite volume. Cross-host deployment uses Supabase, not ephemeral SQLite or in-memory quotas.

## Explicit snapshot sharing

Private/local by default. Publication captures validated design plus trusted example tasks, excluding private tasks, keys/auth/ownership metadata. Snapshot viewers get no owner's entitlement or mutation controls. Changes remain frozen until explicit republish; only the verified owner can republish/revoke. Hosted publishing needs ENABLE_HOSTED_SHARING=true and VITE_ENABLE_PUBLIC_SHARING=true. The UI labels local previews when hosting is disabled. Database limits five snapshots per owner and thirty writes per rolling day. Public reads include only read-only design/example data.

## Temporary request-count testing switch

Apply reviewed migration 003 after 002, then separately set `request_limits_enabled=false` in the private policy. This explicitly disables per-minute and both lanes’ per-user/aggregate daily request counts. It preserves verified authentication, shared email approval, global concurrency, usage history, accounting, cap/rates, circuit breaker, and the $5 aggregate shared UTC-day spending ceiling. Defaults remain enabled. Re-enable with `request_limits_enabled=true`; existing history immediately counts again. No counter reset or key change is needed. This switch does not make a reached shared spending ceiling disappear, and does not bypass a tripped breaker.

The visual-lab provider schema uses bounded integer RGB colors, enum style names, and six visual CSS/SVG strings. Server/client validation enforces the string grammar and complexity limits after generation, because the provider does not enforce those string constraints. Legacy geometry remains readable but is no longer redundantly requested from the model. Known validation failures include only an allowlisted category, final-content length and finish/usage metadata, never raw output. Historical failed output was not retained, so its exact rejection remains unconfirmed.

## Renderer-only fixtures

`/visual-fixtures.html` exercises curated notebook and leather materials without inference. Fixture mode never initializes the auth client, reads or writes real task/key/snapshot storage, resolves snapshot query parameters, or allows account, dictation, sharing or paid style actions. Task edits are ephemeral within the fixture. Live-generation QA and any production release remain separate gates.

Preview deployments (VERCEL_ENV=preview) additionally return fixed-vocabulary CSS rejection reasons, recognized properties and recognized features such as units/functions. Unknown names become `other`. Raw CSS values, response bodies, prompts, tasks and credentials are never included. Production omits these extra fields; accounting rules are unchanged.

Provider output now receives the same cosmetic normalization in every environment before strict validation: bounded CSS lengths are clamped, harmless unsupported paint/font declarations are dropped, and safe declarations are preserved. URLs, dynamic functions, executable syntax, unknown fields, layout/control properties and malformed design structure remain hard failures. Invalid optional SVG is discarded as a whole, never repaired into executable content. This behavior is identical for preview and eventual production promotion; only diagnostic verbosity is preview-gated.

Invalid optional scene/card SVG is omitted before the validated theme reaches a browser. Fixed warning codes produce a visible message that artwork was omitted; no rejected markup is returned or rendered. Non-string decoration fields and unknown/executable design fields remain errors. Essential material textures belong in bounded CSS gradients so optional artwork failures do not discard the usable design.

Card material paint remains visible through transparent title/metadata containers. Actual title text, task IDs, priority/tag labels and action buttons retain opaque validated surface backing; wrapped titles clone their backing on each line. Title click targets, keyboard focus, movement and task state are unchanged.
